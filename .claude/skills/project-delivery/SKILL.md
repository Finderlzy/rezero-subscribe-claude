# 项目交付验收

读取 [开发流程契约](../shared/workflow-contract.md)、项目指南、PRD 验收、架构/接口、里程碑、已有交付记录和真实代码状态。以目标版本或提交为验收基线，核对所需任务已集成；任务全部关闭不是集成证据。缺少实现时列出差距并按授权修复，不把未完成范围悄悄排除。

## 验证交付物

根据用户核心流程制定相称的验收矩阵：需求标识、场景、验证方式、结果与证据。覆盖成功路径和影响使用的关键失败/边界；CLI 验证完整命令链及持久化，UI 验证真实交互与重要状态，服务验证实际接口与必要集成。使用隔离测试数据和项目指定环境，不能用 mock 成功冒充真实外部集成通过。

执行项目要求的回归与构建，检查实际产物。按交付方式在干净的临时目录或隔离环境验证安装、启动和代表性流程，尽量避免依赖源码目录或开发机隐式配置。没有打包步骤的项目验证其实际运行入口，不强造安装包。记录运行环境与基线；验收后产物改变则补验受影响部分。

发现可修复的交付缺陷时按 [task-implement](../task-implement/SKILL.md) 的纠错规则处理，保留回归检查；重大范围或架构变化先解决权威约定。外部依赖无法验证时明确未验证项及对交付的影响；关键验收未通过不能宣称可发布。

## README 与交付记录

已有 README 局部更新，没有则在交付需要时创建。写实际支持的能力、先决条件、安装启动、最小使用示例、必要配置和已知限制，按项目读者需要补充开发命令。文档可以在早期建立，交付时必须核对准确性；实际执行关键命令，不能把计划写成事实。不暴露凭据，不把实现细节堆进用户操作流程。

在现有交付记录或 `docs/delivery.md` 留下基线、范围、验收结果、产物位置、环境及未解决项，区分通过、失败、未执行与不适用；证据规模与项目相称，不保存无用海量日志。首次准备发布或约定版本节点到达时由 task-closeout 按既有版本机制处理，不因每次验收重复升版。

## 交付与发行

由本 Skill 统一调用 [task-closeout](../task-closeout/SKILL.md)，保留必要交付产物，清理本次测试目录和临时数据。报告验证范围、结果、README、交付记录和产物入口。

用户明确要求正式发行、打标签或部署时，完成可审查产物与必要检查后按已有授权和实际发布工具执行；未授权时交付准备好的结果，不默认发布。无发布工具或流程则说明缺口。发布成功需查询实际结果，不能以提交、推送或构建成功替代。发布后复盘由 architecture-review 按需执行。
