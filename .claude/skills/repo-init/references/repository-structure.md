# 仓库目录与文件归属

本参考用于 repo-init 完成输入读取后确定目录规则。以当前项目架构、模块职责和工具发现机制为依据；下表中的路径是无既有约定时的候选，不要求全部创建。

| 文件类别 | 归属原则与候选位置 |
| --- | --- |
| 根目录入口 | 保留 README、AGENTS.md、许可证及工具要求的清单、锁文件和配置；CONTEXT.md 沿用共同契约或项目已定位置。根目录不承接所有零散文档或脚本。 |
| 项目文档 | PRD、调研、架构、接口、设计、决策及交付资料沿用权威位置；无约定时可按用途放入 docs/，资料增多后再分子目录。README 负责使用入口，AGENTS.md 负责工作规则，不复制设计正文。 |
| 模块源码 | 根据架构职责、依赖方向及框架约束选择 src/、应用目录或包目录；多应用、多包项目按实际边界使用 apps/、packages/ 等。模块内部实现留在模块内，确有多个使用方的公共能力才放共享模块。 |
| 测试与测试数据 | 沿用测试框架及现有布局，选择模块旁测试或 tests/；夹具和快照归属对应测试，避免混入生产资源或临时输出。 |
| 配置与部署 | 工具要求的根配置、CI 和部署发现路径保持原位；可自由定位的配置才按用途归入 config/ 或已有部署目录。环境示例与本地运行数据按用途区分。 |
| 开发及运维脚本 | 放入已有 scripts/ 或对应模块目录，按服务对象区分；运行时业务代码不因可直接执行就归入 scripts/。 |
| 静态资源与数据 | 遵循框架资源目录；可编辑源资源、测试数据、运行数据和生成资源分别归属其使用方，避免用一个 assets/ 承接所有文件。 |
| Agent 相关文件 | AGENTS.md 维护对应作用域规则，兼容入口引用它；共享参考或模板可放已有目录或 .agents/。产品配置保留产品规定路径，Skill 及其 references、scripts、assets 保持自身目录结构，不混入一般项目资料。 |
| 构建输出、日志与缓存 | 沿用实际工具输出配置，注明生成用途与位置，按需引用忽略约定；不把输出当源码，也不借目录规范新增清理策略。 |

对实际适用的类别给出具体路径，不能只抄上表中的候选名。小型 Skill、文档或配置仓库可以完全不需要 src/、apps/ 或 tests/。新增文件按“用途 → 所属模块或使用方 → 既有同类位置”选择归属；没有合适位置时，只有存在实际内容与独立职责才新增目录。

已有文档位置与候选路径不同但职责清晰时保留原位。发现散落文件时，先读内容和引用方，判断是入口、权威正文、模块专属资料还是临时产物，再提出归属。模块边界与设计发生实质冲突时记录具体差异，复用已确认变更；未解决的技术决策不以文件搬迁代替。

指南中的目录树或归属表应能回答“新增接口文档、模块测试、开发脚本和 Agent 参考分别放哪里”。只选当前项目相关示例；已规划但尚不存在的路径标注为计划，现有但待迁移的路径仍如实保留现状说明。
