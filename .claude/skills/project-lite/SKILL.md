# 小项目快速立项

把一个小想法在一次会话内变成可开工的一页简报，不走完整的 PRD、架构、Issues 流程。共同规则见 [开发流程契约](../shared/workflow-contract.md)，其中的代决策、状态分级和 Git 约定照常适用。

## 适用判断

满足以下大部分条件时使用本 Skill，否则建议改用 [project-prd](../project-prd/SKILL.md)：
- 一个人开发，预计 10 个以内任务；
- 核心流程只有一到两条，不涉及多角色权限或复杂外部集成；
- 不需要 GitHub Issues 追踪。

## 流程

1. **读取已有输入**：用户的想法、目标目录现有文件和 AGENTS.md。目标目录不明确时先确认路径。
2. **一轮追问**：列出当前理解和推荐方案，只问会改变范围或验收的问题，按主题编号、一轮问完。用户说“你定”时直接采用推荐方案。
3. **快速选型**：技术栈优先选择项目已有的或用户熟悉的。引入新依赖前用官方文档核对一次用法；需要时快速搜一次现成方案，不写单独的调研文档。
4. **写 `docs/brief.md`**，篇幅控制在一到两屏，结构如下：
   - **目标与非目标**：一句话目标、成功标准、本期不做什么。
   - **边界**：Always / Ask first / Never 各列 2~4 条。
   - **核心流程与验收**：每条验收写成可观察的“操作 → 预期结果”，覆盖主流程和关键异常。
   - **技术栈**：语言、框架、存储、测试和运行方式，每项一句理由。
   - **模块草图**：主要模块及其职责、依赖方向，必要时附一个简短 Mermaid 图。
   - **任务清单**：按可演示的垂直切片（[planning-and-task-breakdown](../agent-skills/plan/planning-and-task-breakdown/SKILL.md)）排序的复选框列表，每项写明验收要点和建议档位（规则见契约“模型档位”），并标出第一个可开工任务。
   - **待定项**：只在确实存在时列出。

   项目有特殊术语时才建 `CONTEXT.md`，否则不建。
5. **最小仓库约定**：目标还不是 Git 仓库时，按 [repo-init](../repo-init/SKILL.md) 的“Git 初始化”一节处理。没有 AGENTS.md 时创建一份简短版本，包含目录约定、运行与测试命令、`brief.md` 入口和 `合并策略: auto`。已有时只补充缺失的入口。
6. **交付**：展示 brief 链接、第一个任务及其建议档位，然后执行 [task-closeout](../task-closeout/SKILL.md)。用户已授权完整开发时，直接按 [task-implement](../task-implement/SKILL.md) 从第一个任务开始；任务来源使用 brief 的任务清单，没有 Issue 时不创建 Issue 分支，按项目分支约定处理。

## 升级到完整流程

出现以下情况时，提示用户切换到完整流程：任务超过约 10 个、出现多角色权限或复杂集成、需要多人协作或 Issues 追踪。切换时 `brief.md` 作为 project-prd 的输入：project-prd 复用其中已确定的内容，只补问缺口，并在原位置生成正式文档，brief 改为指向它们的链接。
