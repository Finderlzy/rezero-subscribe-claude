# 任务收尾

读取 [开发流程契约](../shared/workflow-contract.md) 和适用的 `AGENTS.md`。从任务上下文、操作记录和工具输出确认：目标项目、实际改动、验证结果、临时输出位置。Git 状态不能证明文件归属，也看不到被忽略或写在仓库外的产物，不能靠文件名或修改时间猜测。

本 Skill 只收尾，不反向调用初始化流程，不另建交接日志。收尾完成不代表任务已集成；Release 只按第 8 步处理。

**顺序**：盘点 → 1 文件归位 → 2 忽略规则 → 3 知识同步 → 4 版本 → 必要验证 → 5 清理 → 6 Diff 审查 → 7 Git → 8 标签与 Release。档位内的每一步没有需要时可以不改，但必须检查。验证失败时，修复后回到受影响的那一步，不重跑整套流程。

**档位**（报告中写明）：
- **文档档**：只改了文档或注释，没有改代码、测试、构建配置或 Skill 指令文件时，只做 1、3、5、7。
- **代码档**：其他情况，完整执行。

## 1. 文件归位

- 只整理本次新增、需要保留、但放错位置的文件，按现有目录职责归位，并同步导入、配置、测试、脚本和文档中的引用。
- 工具要求固定位置的文件不要移动。无用产物留给第 5 步清理。不补建空目录或脚手架。
- 实际移动前读取 [文件操作细则](references/file-operations.md)。不覆盖已有文件；归属不明的保留并说明。

## 2. 忽略规则

- 只为确实不应纳入的产物补充精确规则：Git 写 `.gitignore`，其他工具写各自的忽略文件。不为凑格式创建空的忽略文件。
- 避免宽泛规则误伤源码、测试、配置或交付物。用 `git check-ignore -v -- <path>` 核对：该忽略的确实被忽略，新增的正式文件没有被误忽略。
- 不自动执行 `git rm --cached`。

## 3. 知识同步

只处理本次确认、实现或验证得到的事实，不记录猜测、临时状态或修复经过。

| 内容 | 写到哪里 |
| --- | --- |
| 术语 | `CONTEXT.md` |
| Agent 规则、关键约束 | 对应作用域的 `AGENTS.md` |
| 需求和验收变化 | 现有需求文档或 brief |
| 架构、目录职责 | 现有架构文档 |
| 里程碑、任务状态 | 实施计划或任务系统，只依据实际交付证据更新 |
| 技术选择与取舍 | `docs/adr/` 或架构文档 |

- 局部更新原文件，同一内容只在一处维护，没有合格结论就不改。
- README 已有，且本次改动让说明、命令或链接失效，或者新能力缺少使用入口时才更新；没有 README 时不新建，首次创建由 project-delivery 负责。
- 如果环境中有 `neat-freak`，可以把本步交给它的“文档同步”档，并限定在本次改动范围内；没有时按上面的规则自行完成。

## 4. 版本

- 识别版本的权威来源和最近一次发布基线，对基线以来全部未发布的变化取最高 SemVer 级别。
- 对 Skill 而言，触发条件、必需输入、默认行为、输出和依赖都属于公开契约，不能因为“只改了文字”就认定没有影响。
- 按项目 `AGENTS.md` 的 `发布策略` 自行决定，不询问用户：`auto`（默认）直接修改版本号，`manual` 只给建议。用户本次指令优先。
- 实际升版、没有版本机制、处于 `0.x` 或预发布、兼容性难判断时，读取 [版本维护细则](references/versioning.md)。

## 5. 清理

- **每次必查**，包括仓库外本次工具写入的位置。Windows 下检查本次用到的 `$env:TEMP`、`$env:TMP` 专用子目录。不能以“Git 工作区干净”为由跳过。
- 只删除同时满足三个条件的产物：本次产生、用途已结束、不再被依赖或交付。正式测试、夹具、快照、交付文件和仍需排查的证据都要保留；共享缓存和来源不明的文件不要整批删除。
- 删除前读取 [文件操作细则](references/file-operations.md)。确定可删的直接删除，有疑问的保留并说明。报告的释放量只按实际测量的文件大小计算。

## 6. 防作弊 Diff 审查

task-implement 已在独立评审前执行并裁决、之后没有再改代码或测试时，沿用其结果，不重跑。否则提交前审查全部待提交差异，包括未跟踪的新文件（方法参考 [constraint-driven-development](../agent-skills/define/constraint-driven-development/SKILL.md)）。

1. **先跑脚本**：在目标仓库中执行 [diff-audit.ps1](scripts/diff-audit.ps1)。工作区混有用户改动或只需补查收尾期间的改动时，用 `-Path` 限定；Issue 分支可以加 `-Base <基线 SHA>` 覆盖整个分支。
   ```powershell
   powershell -ExecutionPolicy Bypass -File <本 Skill 目录>\scripts\diff-audit.ps1 [-Path <本次文件>] [-Base <基线>]
   ```
   退出码 0 表示未命中，1 表示有命中需要裁决，2 表示脚本无法运行。退出码 2 不能当作通过，要改为人工完成下一步的全部检查。
2. **逐项裁决命中**：报错压制、跳过或聚焦用例、删除测试或断言、未实现桩、空 catch、调试残留。已有设计明确要求的（例如生成代码里的压制、CLI 的正常输出）记为“合理”，并写明依据；其余的回去修复真实原因，修复后重跑脚本。
3. **人工补查脚本查不到的部分**：被放宽的匹配条件或阈值、被改弱的断言（例如 `toEqual` 改成 `toBeTruthy`）、硬编码的测试值、改动配置让检查不再运行。

不能带着未裁决的命中提交。无法自行判断的疑点，请用户裁决。报告中写明脚本的退出码、命中数和裁决结果。

## 7. 提交、推送与合并

- 读取 [Git 操作细则](references/git-delivery.md)，只提交本次的完整改动。commit 信息根据实际差异编写，沿用项目习惯；没有约定时用简洁的中文。
- Issue 任务的合并步骤见 Git 操作细则。
- 推送失败时保留本地提交，不重试，把提交号、失败原因和手动推送命令交给用户。没有改动不创建空提交；没有 Git 仓库时不自动初始化，报告未提交，并提示用 repo-init 初始化。

## 8. 标签与 Release

`发布策略: auto` 时，本次升了版本或当前版本还没有标签，就按 [发布细则](references/release.md) 自行打标签、发布 Release，不询问用户；`manual` 时跳过。版本提交进入 main 前不打，报告“待合并后补打”。部署和包仓库发布仍需单独授权。

## 报告

收尾前确认：移动后工具仍能发现文件、引用有效，忽略规则匹配正确，清理目标已删除且必要产物还在，最终差异里没有无关的移动或删除。

简短报告：实际做了哪些调整（附文件链接）、版本（建议或已更新）、标签与 Release 结果或未执行原因、Diff 审查结论、提交号、推送和合并状态、清理结果和实测大小、保留项和缺口。没有变化的项合并成一句，不把收尾报告写进 `AGENTS.md`。
