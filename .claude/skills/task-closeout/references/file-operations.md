# 文件移动与清理操作细则

## 移动文件

移动前核对源和目标绝对路径均在目标项目或明确授权目录内，检查同名冲突，不覆盖现有文件。递归移动前核对全部内容及路径边界，不沿目录联接或符号链接跨范围操作。Windows 使用同一 PowerShell 流程和 `Move-Item -LiteralPath`。同步导入、配置、脚本、测试、文档及打包清单中的路径；确认工具仍能发现文件。原目录仅在本次创建、已经为空且无用途时删除。

## 日志、缓存与 C 盘空间

每次检查本次工具实际写入的位置，包括仓库内隐藏或被忽略的目录，以及从命令输出、工具配置或任务记录确认的项目外目录。Windows 特别检查本次使用的 `$env:TEMP`、`$env:TMP` 下的专用子目录和 C 盘上的任务输出；变量值或常见目录名只是定位线索，不是整目录删除授权。

对确认属于本次的候选项统计文件大小，优先清理已无用途的大日志、重复构建产物、临时下载和缓存。缓存可重新生成不等于已经无用：仍用于运行、交付或近期必要验证的内容保留。本次没有创建记录时，不把整个用户缓存或系统临时目录当作任务产物。

共享包管理器缓存、浏览器数据、Agent 历史、其他项目缓存、依赖安装目录和系统文件不因 C 盘空间少而整批清除。若任务记录显示共享缓存占用明显增长，但无法区分本次文件，可只读检查相关工具提供的缓存大小或清理预览，给出具体目录、体积和可选清理方式；只有用户另行授权该范围，才执行工具支持的定向清理。不自行更改全局缓存位置或长期保留策略。

只停止本次启动且已完成用途的进程以释放文件占用；不终止其他进程或删除仍在写入的日志。删除失败时保留并报告路径与原因，不声称已释放空间。根据成功删除的文件大小报告清理体积，注明是文件大小合计；未测量时不编造数字，也不把磁盘可用空间变化全归因于本次清理。

## 执行删除

仅删除同时满足“本次产生、用途已结束、不再被依赖或交付”的明确路径；清理符合条件的文件无需逐项向用户确认。归属或用途仍不明确时，先完成确定可清理的部分，保留疑问项并简短说明原因，必要时询问具体文件，不一概停止收尾。

删除前核对解析后的绝对路径位于本项目或已确认属于本次任务的专用输出目录；递归删除目录前核查其内容均符合条件。遇到符号链接、目录联接或其他重解析点时，不沿链接递归删除目标。不要使用 `git clean -fdx`、通配删除所有测试或缓存目录等全仓库清理方式，也不通过重置、还原文件来清除用户改动。

Windows 下使用同一 PowerShell 流程完成核对与删除，使用 `Remove-Item -LiteralPath` 指定已确认路径，不把枚举结果拼接成 `cmd /c` 删除命令。清理命令失败时核对原因，不扩大删除范围重试。

清理后确认目标已移除、必要交付物仍存在、引用未悬空，并核对项目差异没有无关删除。后续验证若再次生成临时产物，交付前补做同范围清理；不为了清理重复运行会生成同样产物的整套测试。
