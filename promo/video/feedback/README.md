# 读者反馈截图

宣传片开头的“读者反馈”段（抖音版 0–6 秒、B 站版 0–8 秒）用这里的截图。截图要登记在 `list.json` 的 `items` 里才会上片，按登记顺序出场；`render.mjs` 把它交给动画（摆法见 `../feedback.js`），配乐脚本按里面的张数卡点。

**只放真实读者的反馈，不编造、不改字、不用假截图。** 一张都没登记时，动画里画红色虚线占位框，`render.mjs` 拒绝渲染整片。

## list.json

```json
{
  "items": [
    { "file": "purchase-success.jpg", "kind": "phone", "focus": [132, 866, 662, 322], "note": "说明" },
    { "file": "comment-thanks.png", "kind": "card", "note": "说明" }
  ],
  "unused": [{ "file": "comment-question.png", "note": "为什么不放" }]
}
```

- `kind: "phone"`：手机竖屏截图。只用第一张，装进手机框；`focus` 是截图里要放大的区域（`[x, y, 宽, 高]`，截图像素），比如订阅成功的弹窗，会先框出来再放大成卡片。
- `kind: "card"`（默认）：横条截图，比如评论区的一条评论。手机截图之后一张张浮上来，最多用前 4 张。
- `unused`：放着但先不上片的，写明原因；`render.mjs` 不读它。

## 放进来之前

- 打码：去掉昵称、头像、群号、QQ 号、手机号、订单号、IP 属地等能认出人的信息。
- 内容：画面不能出现翻墙、代理、节点这类词，也别带商家名（见 `../README.md` 的拍摄约束），有的话换一张或裁掉。
- 文件名用英文（`comment-xxx.png`），方便在 list.json 里引用；只改名，不改图片内容。
- 尺寸：手机截图原图就行（宽 900 以上）。横条截图宽高比 3:1～5:1 最合适，截图时把浏览器缩放到 150%～200% 截，宽 600～1200 像素，放大到视频里才清楚；几张宽度尽量接近，字号就一致，太宽的会被缩小。
- 张数：1 张手机截图 + 2～3 条评论效果最好；只有手机截图或只有评论也可以。

这个目录里的截图会被 git 跟踪，提交前再确认一遍已经打码。
