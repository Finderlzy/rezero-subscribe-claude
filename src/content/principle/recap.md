# 小结：从服务器到代理软件

前面一下子讲了好多新东西：IP、节点、ISP、防火墙、代理软件、tun 模式。这一页不讲新的，只把它们串起来，看看你在电脑上打开 claude.ai 的那一刻，到底发生了什么。

**先回顾一下，我们要过两道关**

1. **防火墙**：守在国内网络通往海外的出口上，看你要去哪儿，不让过的就拦下来。
2. **claude 的风控**：看请求来自哪个 IP。来自中国的，制裁；来自机房的，像在用代理，容易封号。

前面做的所有事，都是为了把这两道关过了。

**打个比方**

把上网想成寄信。你访问 claude，就是给 claude 寄一封信，信封上写着你的寄件地址，也就是 IP，claude 看到寄件地址是中国，就不回信，还要制裁你。

- **节点**：你在海外找了个朋友，信先寄给他，由他用自己的地址转寄给 claude。claude 看到的寄件地址就是海外的了。
- **ISP 代理**：可这个朋友住在机房里，claude 一看就知道是代收代寄的。所以朋友再把信交给一个住在居民区的邻居，由邻居寄出去。claude 看到的就是一个普通居民的地址。
- **防火墙**：你的信要寄出国，先得过国内邮局的检查。邮局一看信是寄给海外朋友、要他帮忙转寄的，就会扣下来。
- **代理软件**：它把你的信装进一个不透明的信封，外面写成寄给一家普通的大公司。邮局看不出里面是什么，就放行了。朋友收到后拆开外层信封，再帮你转寄。
- **tun 模式**：规定家里所有人寄的信，都必须先交给代理软件装信封，谁也不能自己偷偷寄。

claude 回信的时候，也是原路返回：claude → 邻居 → 朋友 → 代理软件拆信封 → 你。

**真实的路线**

换回真实的名字，以方案一为例，就是这样一条路：

```
你的电脑/手机
  │  tun 模式：整台设备的流量都交给代理软件
  ▼
代理软件
  │  加密，伪装成访问普通的大网站
  ▼
防火墙（国内网络的出口）
  │  看起来是一次普通的上网，放行
  ▼
节点（海外的服务器，上面跑着 Xray）
  │  拆开伪装，看你要去哪儿
  ├─ 访问 claude（还有 ipinfo.io）→ 转交 ISP 代理 → claude 看到的是 ISP 的 IP
  └─ 访问其他网站 → 直接从服务器自己的出口出去
```

**每一样东西管什么**

| 东西 | 是什么 | 解决什么问题 | 在哪一步弄好的 |
| --- | --- | --- | --- |
| 节点 | 海外的服务器，装上 Xray 替你收发请求 | 让请求带上海外的 IP，能到达 claude | [[二、购买服务器]]、[[三、把服务器变成节点]] |
| ISP 代理 | 运营商的 IP，看起来像普通人在上网 | 让 claude 觉得你是普通人，不封号 | [[一、白嫖 ISP]]、[[四、购买 ISP 代理]] |
| 代理软件 | 装在你设备上的软件 | 加密、伪装，过防火墙 | [[导入代理软件]] |
| tun 模式 | 代理软件的一种接法 | 让所有流量都走代理，一个都漏不掉，软件也看不出你在走代理 | [[导入代理软件]] |
| 节点链接 | 写着节点在哪儿、怎么加密伪装 | 代理软件靠它找到节点 | [[三、把服务器变成节点]] |

**方案二、三有什么不一样**

- **方案二**：服务器自己就是住宅 IP，所以少了“转交 ISP 代理”这一步，节点直接把请求发给 claude。
- **方案三**：节点和住宅 IP 都是商家准备好的，你只用导入节点链接。

其他部分，代理软件、tun 模式、防火墙，三个方案都一样。

**测 IP 测的是什么**

上一页测 IP 质量，测的就是这条路的最后一环：claude 看到的那个 IP 到底怎么样。只有它是住宅/ISP 类型、风险分低，前面这一路才算没白搭。

**还剩什么**

这条路已经搭好了，请求从这条路走，不会露出你在国内。但路外面还有几条小缝：查电话簿的 DNS、浏览器的 WebRTC、IPv6。下一页就把它们一个个堵上。
