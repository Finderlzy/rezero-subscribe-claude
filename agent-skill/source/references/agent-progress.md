# 进度文件：位置、模板和更新规则

本文件是 Agent 方法文件（FR-110、FR-111，架构 §16.5）。写给 Agent 看，读者不需要读它。

## 位置

固定在这两个位置之一，不要另建文件：

- macOS / Linux：`~/rezero-subscribe-claude-progress.md`
- Windows：`%USERPROFILE%\rezero-subscribe-claude-progress.md`（PowerShell 里是 `$env:USERPROFILE\rezero-subscribe-claude-progress.md`）

放在读者的用户目录下，是因为读者能看见、也能自己删掉；删掉就等于重新开始。不要放进 Skill 目录、仓库或临时目录：临时目录会被收尾清理删掉，那等于每次都从头来。

读者说「继续」「接着做」时，先读这个文件；文件不在就是新读者，按 `SKILL.md` 的开场流程走完、读者确认风险之后再创建。

## 空模板

第一次创建时原样写入下面的内容，方括号换成读者的实际情况（方括号本身不要留着）：

```markdown
# 订阅 Claude 进度

删掉这个文件就是重新开始：下次对 Agent 说「带我订阅 Claude」或「继续」，它会从下面的记录接着来。

- Skill 版本：[SKILL.md 的 metadata.version]
- 电脑系统：[Windows / macOS / Linux]
- 节点方案：[方案一 / 方案二]
- 手机系统：[iPhone / iPad 或 安卓]
- 先用两天开始日期：[YYYY-MM-DD；还没到这一步就写 未开始]

## 步骤

| 页面标识 | 状态 |
| --- | --- |
| preface | 完成 |
| overview | 进行中 |
| plan1 | 未开始 |
| plan2-residential-server | 未开始 |
| client-desktop | 未开始 |
| iphone-prepare | 未开始 |
| iphone-subscription | 未开始 |
| android-prepare | 未开始 |
| android-subscription | 未开始 |
| maintenance | 未开始 |
| afterword | 未开始 |

## 验收结果

| 验收项 | 结果 |
| --- | --- |
| 节点自测 Reality / Hysteria2 | 未测 |
| 电脑端出口 IP 和 AS Type | 未测 |
| DNS 泄漏 | 未测 |

| 浏览器报告的时区 | 未测 |

```

- 步骤状态只用「未开始」「进行中」「完成」三个词；验收结果只用「通过」「没通过」「未测」。
- 页面标识就是 `SKILL.md` 路线表里的「页面标识」列，一个都不要改、不要增删行。
- 读者还没走到的那条分支（比如选了方案二时的 `plan1`、选了 iPhone 时的 `android-*`）一直留「未开始」，这不是漏掉；只更新自己这条路线上的页。
- 页面只标记到「页」这一层，不再拆小节。走到哪一小节由 Agent 读该页的参考文件判断。

## 不记什么

进度文件里**不要出现**：

- 密码（root 密码、住宅 ISP 代理的密码、面板密码、Apple ID 和 Google 账号的密码）；
- 服务器 IP、住宅代理的地址、任何测出来的 IP；
- 节点链接（`vless`、`hysteria2`、Clash 配置）；
- 邮箱、账号名、手机号。

验收项只写「通过 / 没通过 / 未测」，**不要写测出来的具体 IP 和分数**。读者把文件发出来求助时，里面不该有任何能直接拿去用或能定位到他的东西。

## 什么时候更新

每次状态变了就写回文件，不要等到最后一起补：

1. 完成一步：把这一页改成「完成」，按路线表把下一页改成「进行中」。
2. 读者说「跳到某一步」：只把目标页改成「进行中」，不要替读者把中间的页标成「完成」。
3. 读者改了节点方案或手机系统：改对应那两行，并把受影响分支的页恢复成「未开始」。
4. 验收项出结果：改成「通过」或「没通过」。
5. 到「先用两天」：把开始日期写成读者当天的本机日期，格式 `YYYY-MM-DD`。
6. 读者说「重新开始」：先问清楚（会清空全部记录，包括已经问过的系统和方案），确认后删掉或清空文件，再从开场重来。没确认不要动。
7. 收尾清理时：核对文件里没有上面「不记什么」列的东西。

Skill 版本写 `SKILL.md` 里 `metadata.version` 的值，生成后是固定的字符串；不要写站点更新日志里的日期。

## 读者回来时，怎么判断停在哪一步

1. 步骤表里状态是「进行中」的那一页，就是停的地方。先读它的参考文件，再说「你停在……要不要接着做」。
2. 没有「进行中」时，找最后一个「完成」，按路线表取它的下一步。
3. 全都没开始时，从 `preface` 之后的第一页开始。

恢复时不要重问已经在文件里答过的东西（电脑系统、节点方案、手机系统）；读者说要改再改。也不要一上来就把整条路线复述一遍，先说停在哪、下一步做什么。

## 「先用两天」怎么算

有些步骤要隔天：iOS 和安卓的「先用两天」。到了这一节，把开始日期记进进度文件，然后告诉读者到时候回来说「继续」。

读者回来说「继续」时：

- 用**本机当前日期**减开始日期，按整天算，别按小时估。
- 不满两天：说清楚还要等多久（例如「还差 1 天」），**不要催读者往下走**，也不要提前引导后面注册 Claude 这些步骤。
- 满两天：从同一页里「先用两天」后面的小节接着引导。iOS 和安卓都先到同页的「修改 Google 账号地区（可选）」，再到「注册 Claude」；具体小节名以该页参考文件为准。

开始日期是空的，说明还没到这一步，不要拿它算。
