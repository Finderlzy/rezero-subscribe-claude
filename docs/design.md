## 1. 设计调研：学到了什么，怎么用

用户要求先学习网站设计，**不能照抄**。所以下面只提炼各个来源的原则，再结合本站的读者情况转成自己的决定；不借用任何站点的版式、配色、字体、图标或文案。

| 来源 | 学到的原则 | 本站的做法 |
| --- | --- | --- |
| [GOV.UK：Step by step navigation](https://design-system.service.gov.uk/patterns/step-by-step-navigation/) | 有明确起点和终点、必须按顺序做的流程，要让人随时看到整条流程；“或”步骤（二选一）要和普通步骤区分开；不要让用户在流程之间来回绕 | 目录按章节列出整条路线，分叉点显示成“或”分组；当前路线以外的步骤列出来但弱化（FR-16）；常见问题只有“返回”，不接进步骤序列，避免绕圈 |
| [GOV.UK：One thing per page](https://www.gov.uk/service-manual/design/form-structure) | 每页只放一件事，用户更容易专注，在手机上也更好用，出错时也更容易回到原处；分支只让用户看到和自己相关的内容 | 一页一步（FR-10）；分叉点单独做成选择页；选了方案三，就不会再看到方案一的步骤 |
| [NN/g：Wizards](https://www.nngroup.com/articles/wizards/) | 显示一共几步、现在在第几步；“下一步”按钮写出要去哪里，不要只写“下一步”；允许中途离开，回来后能接着做；每一步都应该包含完成这一步需要的全部信息 | 顶部显示“第 2 步，共 5 步”；按钮写成“下一步：白嫖住宅 IP”；有“继续上次”（FR-18、FR-50）；视频、命令、截图都放在当前步骤里 |
| [Diátaxis：Explanation](https://diataxis.fr/explanation/) | 操作内容和原理解释要分开：原理会把操作内容撑散，原理写进操作里也会让操作更难找；操作内容可以链接到原理 | “操作 / 原理”是两层，不是两套页面：原理只放在 `[!why]` 块里；操作视图把它收起来，只留一行提示“这一步有原理说明”（见 §4.3） |
| [web.dev：Third-party facades](https://web.dev/third-party-facades) | 第三方嵌入先放一个很轻的门面，用户点击后再加载真播放器 | 自己做视频门面：**不加载 YouTube 封面图**（国内打不开，点击前也不应该请求第三方，对应 NFR-03/04），只显示本站绘制的占位和平台名 |
| [WCAG 1.4.8](https://www.w3.org/WAI/WCAG21/Understanding/visual-presentation.html)、[W3C clreq](https://www.w3.org/TR/clreq/) | 中日韩文本每行不超过约 40 字；标点按大陆规范（GB/T 15834），用弯引号；省略号、破折号不能断在两行 | 正文最大宽度 `38em`（约 38 个汉字）；不替换作者原文标点；`line-break: strict` |
| 系统字体栈（[W3C 系统字体对照](https://w3c.github.io/clreq/others/system-font-mappings.html)） | 不同平台的中文字体不一样，要按平台排顺序；拉丁字体放在前面 | 只用系统字体，不加载网页字体（NFR-03 也要求不依赖字体 CDN），见 §3.2 |
| 前端工程规范（[frontend-ui-engineering](../.claude/skills/agent-skills/build/frontend-ui-engineering/SKILL.md)） | 参考只能当证据，不能当模板；避免“AI 味”：紫色渐变、到处大圆角、千篇一律的卡片网格、重阴影、空洞的 Hero | §6 的“拒绝清单” |

**读者情况**（来自需求 S1–S6，是所有取舍的出发点）：读者一手拿手机看，另一台设备上照着操作；每一步都要复制命令、对照截图；一半读者只想照做，一半想弄懂原理；可能读到一半退出，第二天再回来。

## 2. 设计方向：“随身操作手册”

本站更像一本**放在键盘旁边、翻开就能照做的手册**，而不是一个博客或一个文档站。由此得到四条原则，冲突时按顺序取舍：

1. **一眼知道我在哪、还剩多少**：每页的顶部都显示章节、第几步、共几步。
2. **照做的东西最显眼**：命令、按钮名、截图是主角；原理是可以展开的第二层。
3. **单手能翻页**：在手机上，“上一步/下一步”固定在屏幕底部拇指能够到的位置。
4. **安静**：只有一种强调色，没有装饰图，也没有动效表演。读者本来就紧张（怕被封号），页面不要再添乱。

**名字的处理**：「Re:从零开始」只体现在文字上。首页标题用大字号排版，不使用番剧的图片、角色、配色或 Logo（需求 §1）。也不使用 Anthropic / claude 的品牌色或标志，避免读者误以为这是官方页面。

## 3. 视觉基础（设计令牌）

### 3.1 颜色

只用语义令牌，不在组件里直接写色值。浅色和深色主题都按 `prefers-color-scheme` 自动切换，首期不提供手动切换。

| 令牌 | 用途 | 浅色 | 深色 |
| --- | --- | --- | --- |
| `--bg` | 页面底色（暖白纸色） | `#F7F5F0` | `#171614` |
| `--surface` | 代码块、面板 | `#FFFFFF` | `#201F1C` |
| `--text` | 正文 | `#1D1C1A` | `#E9E6E0` |
| `--text-muted` | 次要文字、弱化的其他路线 | `#5E5A53` | `#A39E95` |
| `--border` | 分隔线、面板和代码块的边框 | `#DDD8CE` | `#34322E` |
| `--control-border` | 控件边框：“跳到正文”、次按钮、两段式切换、复制和关闭按钮、目录里的“切换”“清除进度”、上一步、选择页的选项块（#21） | `#8A8478` | `#736E65` |
| `--accent` | 唯一的强调色（墨绿）：主按钮、当前步骤、链接 | `#0F5F58` | `#5CC2B5` |
| `--accent-contrast` | 主按钮上的文字 | `#FFFFFF` | `#0B1F1D` |
| `--why-bg` / `--why-rule` | 原理块（暖色，表示“解释”，和操作内容区分开） | `#FBF2DF` / `#B7791F` | `#2A2418` / `#D9A54A` |
| `--caution-bg` / `--caution-rule` | 风险提示（开始之前） | `#FCEBE7` / `#B23A26` | `#2E1C18` / `#E07A66` |
| `--focus` | 键盘焦点环 | `#0F5F58` | `#5CC2B5` |
| `--backdrop` | 浮层（看大图、目录抽屉）背后的遮罩 | `rgb(0 0 0 / 65%)` | `rgb(0 0 0 / 75%)` |
| `--video-bg` / `--video-fg` | 视频门面的深色占位和上面的播放图标、文字（#17） | `#1D1C1A` / `#F7F5F0` | `#0E0D0C` / `#E9E6E0` |

要求：正文与背景对比度 ≥ 4.5:1，大字和控件边界 ≥ 3:1。实现时用工具实测上表的每一组颜色，不达标就调整色值并回写本表。

实测（#21，`src/styles/tokens.test.ts` 按 WCAG 2 公式从 `tokens.css` 读值计算，改令牌时自动复核）：文字类组合最低是深色的 `--text-muted` 对 `--why-bg` 5.78:1，其余都在 6:1 以上；浅色 `--why-rule` 对 `--why-bg` 3.27:1、对 `--bg` 3.34:1，刚过 3:1。原来的 `--border` 对底色只有 1.30–1.42:1，当分隔线够用，当控件边界不达标，所以拆出 `--control-border`（浅色对 `--bg`/`--surface` 3.41/3.72:1，深色 3.57/3.25:1）；分隔线、面板、代码块、表格仍用 `--border`。状态不能只靠颜色表达，例如当前步骤还要加粗并标 `aria-current`，弱化的路线还要标出“其他路线”文字。

### 3.2 字体与排版

```css
--font-sans: system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial,
  "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC",
  "Source Han Sans SC", sans-serif;
--font-mono: ui-monospace, "SFMono-Regular", "Cascadia Code", "JetBrains Mono",
  Menlo, Consolas, monospace;
```

| 层级 | 手机（<720px） | 桌面 | 行高 | 字重 |
| --- | --- | --- | --- | --- |
| 首页大标题 | 32px | 44px | 1.25 | 700 |
| 步骤标题 h1 | 24px | 30px | 1.35 | 700 |
| 正文内小标题 h2/h3 | 19 / 17px | 21 / 18px | 1.4 | 600 |
| 正文 | 17px | 18px | 1.8 | 400 |
| 辅助文字（进度、标签） | 14px | 14px | 1.5 | 500 |
| 代码 | 0.875em | 0.875em | 1.6 | 400 |

- 正文宽度：`max-width: 38em`。
- 段落间距 `0.9em`；列表项间距 `0.4em`。操作步骤大多是编号列表，列表编号要和正文左对齐，不能缩进得太深。
- 中西文之间的空格以作者原文为准，CSS 不自动加；可以渐进使用 `text-autospace`，不依赖它。
- 原文里的 `**加粗**` 是“照做的关键点”，用 600 字重表示，不改颜色。

### 3.3 间距、圆角、阴影

- 间距只用这组刻度：`4 8 12 16 24 32 48 64`（px）。
- 圆角：控件 6px，面板 10px，图片 6px；不用胶囊形的大圆角。
- 不用阴影表现层级，用 1px 边框。只有浮层（目录抽屉、看大图）可以加一层很淡的阴影：令牌 `--overlay-shadow`，浅色 `0 0 24px rgb(0 0 0 / 12%)`，深色 `0 0 24px rgb(0 0 0 / 50%)`（深色底上 12% 看不出来）；首期只有宽屏的目录抽屉用到（#18）。
- 图标：全部自己画，内联 SVG，统一 1.5px 线宽、24px 网格，大约 8 个（菜单、左右箭头、复制、已复制、播放、外链、关闭）。不引入图标库，界面上不用 emoji。

## 4. 页面结构

### 4.1 步骤页（最重要的页面）

```
手机（<720px）                          桌面（≥1100px）
┌──────────────────────────┐           ┌────────────┬──────────────────────────────┐
│ ☰目录  一、住宅IP 2/5  操作|原理 │ ← 顶栏吸顶 │ 路线目录    │ 一、准备住宅 IP · 第 2 步，共 5 步 │
├──────────────────────────┤           │（常驻侧栏）  │ 白嫖住宅 IP          操作|原理 │
│ 一、准备住宅 IP · 第2步，共5步 │           │ ● 开始之前   │ [视频门面 16:9]                │
│ 白嫖住宅 IP（h1）          │           │ ● 整体思路   │ 正文（≤38em）                  │
│ [可跳过]                  │           │ 一、准备住宅IP│  ┊ 原理块（原理视图才展开）      │
│ [视频门面 16:9]            │           │  ✓ 买服务器  │                              │
│ 正文……                    │           │  ▶ 白嫖住宅IP │ ┌ ← 上一步 ─┐ ┌ 下一步 → ───┐ │
│ 「这一步有原理说明 · 切到原理」 │           │    连接服务器 │ │ 买服务器   │ │ 连接服务器   │ │
├──────────────────────────┤           │  或：方案二…  │ └──────────┘ └────────────┘ │
│ [← 上一步] [下一步：连接服务器 →]│ ← 底栏吸底 └────────────┴──────────────────────────────┘
└──────────────────────────┘
```

- **顶部**：章节名 + “第 n 步，共 m 步”（按当前路线计数，FR-10）+ 步骤标题。手机上顶栏吸顶，分两行：第一行是“目录”按钮和操作｜原理切换，第二行是完整的“章节名 · 第 n 步，共 m 步”。[#21 选定：原定只放缩写“一、住宅IP 2/5”，但章节没有作者给的短名，自拟缩写等于改内容；360px 下完整进度放得下一行]
- **视频**：放在标题下面、正文上面。读者通常先看一遍视频再照做，放在顶部也方便用手机看视频、在电脑上操作。
- **底部导航**：
  - 手机上吸底固定，高度 ≥ 56px，并适配 `safe-area-inset-bottom`。“下一步”是主按钮，约占 2/3 宽，按钮里写上目标步骤的标题，标题太长就截断；“上一步”是次按钮。
  - 桌面端放在正文结尾，是两个大块链接，分别写出方向和目标标题。
  - 可跳过步骤在“下一步”的上方多一个文字按钮“已有，跳过 →”（FR-15）。
  - 路线的最后一步，“下一步”指向“完成”。
- **目录**：手机上点“☰ 目录”打开全屏抽屉（原生 `<dialog>`）；≥1100px 时显示为常驻左侧栏。目录的内容见 §4.5。

### 4.2 选择页（分叉点）

- h1 直接问问题，例如“你想用哪种方式准备住宅 IP？”；下面是原文章的引导语。
- 每个选项是一整块可点击的区域（一个 `<a>`，不是表单），从上到下排列。块里有：选项名、链路、折腾程度、适合谁，默认选项右上角标“默认”。原文的对比表格拆进这些块里，这样手机上不用横向滚动表格，内容一字不少（FR-03）。
- 已经选过的选项标“当前选择”。点一个选项就记录选择，并进入这个选项的第一步（FR-12）。
- 选择页本身也在步骤序列里，但不计入“第 n 步”。顶部只写章节名，不写步数。
- 底部和步骤页一样有上一步/下一步：“下一步”按当前路线（没选过时按默认选项）进入那个选项的第一步，这样沿默认路线一直点“下一步”就能走完（AC-02）。[#6 选定]

### 4.3 两种视图

- 切换控件是两段式（操作｜原理），在每个步骤页的顶栏里，用 `aria-pressed` 标明当前状态。
- **操作视图**：`[!why]` 块收起，在原来的位置留一行提示：“为什么：<原标题> · 在原理视图中查看”。点这行提示会切到原理视图，并滚动到这个原理块。这样既执行了“操作内容和原理分开”的原则，又让读者知道这里有原理可看。
- **原理视图**：`[!why]` 块在原位展开，用暖色底和左侧竖线，与操作内容区分。
- 没有原理内容的步骤，在原理视图下显示一行“这一步没有额外原理”（FR-31）。
- 切换不刷新页面，滚动位置保持在当前看的内容附近。动效：展开时 150ms 淡入；设置了 `prefers-reduced-motion` 时不加动效。

### 4.4 首页

- 不做 Hero 大图和卡片网格。首页是一页排版干净的文章：大标题「Re:从零开始订阅 claude」，下面一行英文副标题「Re:Zero − Starting Life with Claude」，然后是前言正文。
- 前言下面是行动区：
  - 有阅读进度时，主按钮是“继续上次：<步骤名>”，“直接开始”降为次按钮；
  - 没有进度时，只有“直接开始”一个主按钮。
- 行动区下面用一个编号列表列出七个章节名，让读者知道全程有多长。这个列表只是导航预告，不是目录抽屉。
- 不放致谢和后记（FR-18）。

### 4.5 目录

- 按章节分组。分叉点显示为“或”分组，用短竖线把各选项连起来，旁边有“切换”控件（FR-14）。
- 当前路线的步骤用正常颜色显示；已经读过的步骤前面打 ✓（阅读进度允许时）；当前步骤加粗并标 `aria-current="step"`。其他路线的步骤也列出来，但用弱化色，并带“其他路线”文字；它们可以点开，点开就进入那条路线（S5）。
- 可跳过步骤标“可跳过”。占位步骤标“内容待补”。
- 目录底部是“清除进度”。点了先确认一次，确认后执行（FR-51）。

### 4.6 常见问题页、完成页、找不到页

- **常见问题**：没有上一步/下一步。从步骤链接进来时，标题上方和正文末尾都有“← 返回刚才的步骤：<步骤名>”（FR-20）；直接打开时，显示常见问题列表和目录入口。
- **完成页**：显示“这条路线走完了”、致谢、后记、联系方式，以及“回到目录”“重新开始”“清除进度”。不撒花，也不弹动画。
- **找不到这一步**：一句话说明，加上“打开目录”和“回首页”两个按钮（AC-18）。

### 4.7 内容组件

| 组件 | 规则 |
| --- | --- |
| 代码块 | `--surface` 底色、1px 边框；右上角放“复制”按钮，复制成功后 2 秒内显示“已复制”，并用 `aria-live` 播报；长行在代码块内部横向滚动，不折行（命令必须原样复制，NFR-02） |
| 截图 | 保持原文的显示宽度（`|262` 这类写法）；点击后用 `<dialog>` 看大图，Esc 或点背景关闭；图片必须有替代文字，默认用文件名去掉前缀 |
| 表格 | 在自己的容器里横向滚动，第一列粘性固定（NFR-01） |
| Callout `caution` / `note` | 两种视图都显示；`caution` 用风险色，`note` 用中性面板 |
| 推广链接 | 原文“是否用过”的说明紧跟在链接后面，样式和正文一样，不弱化（三级边界 Always） |
| 内容待补 | 一块中性面板：“这一步的内容待补”，下面放原文章里已有的提示；不画插图（FR-21） |
| 视频门面 | 16:9 区域，本站绘制的深色占位 + 播放按钮 + 平台名。有两个平台时，上方是 B 站 / YouTube 切换，默认 B 站；下方总是放一行“在 B 站打开 ↗ · 打不开？试试换平台或开代理”（只有一个平台时写“打不开？试试开代理”，#17）。没有视频时显示“视频制作中”，高度收成一行，不占 16:9 的空间（FR-40–42） |

## 5. 交互与可访问性

- 所有交互都用原生元素：链接 `<a>`、按钮 `<button>`、抽屉和看大图用 `<dialog>`。页面开头有“跳到正文”链接。
- 焦点环 2px `--focus` 并留 2px 间隔，不能去掉。
- 可点区域在手机上 ≥ 44×44px。
- 底栏吸底时，正文末尾预留等高的空白，最后一段不能被底栏挡住。
- 没有 JS 的时候：页面仍然可读，导航按默认路线（或当前页面所属路线）在构建时直接写进 HTML；视图固定为操作视图。
- 本机存储不可用时，不弹任何错误提示，功能照常用，只是不保存（异常分支）。

## 6. 拒绝清单

以下做法不采用。评审 UI 时逐条核对：

- 照搬 GOV.UK 的视觉（黑黄焦点、Transport 字体、皇冠）、Starlight / MkDocs Material 的布局和配色、博客现有主题；
- 番剧图片、角色、Logo；Anthropic / claude 的品牌色和标志；
- 紫色或靛蓝渐变、玻璃拟态、到处大圆角、重阴影；
- Hero 大图、首页卡片网格、装饰插图、界面里的 emoji；
- 只写“下一步”、不写去哪里的按钮；
- 用颜色作为唯一的状态标识；
- 加载网页字体、图标库、统计脚本、第三方封面图。
