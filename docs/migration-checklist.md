### 导入方式

1. 页面标识（文件名、URL）和元数据只写在 `src/content/principle/<id>.md` 的 frontmatter 里，正文第一行是 `# <重写稿文件名>`。参考页放在 `src/content/reference/`，只有 `# 标题`。
2. 运行 `node scripts/import-rewrite.mjs`：按标题把重写稿正文原样写进去（保留 frontmatter），操作版写进同一标识的 `operation/<id>.md`，被引用、站内还没有的截图从 `附件/` 复制到 `src/assets/screenshots/`。
3. 看脚本报告：新页面、站内多出的页面、附件里也找不到的截图都只报告不处理；新复制的截图逐张核对打码，记进下面的表。
4. 再跑一次确认没有改动，`npm run build` 结束时看“内容提示”。

导入结果（2026-10-15）：原理版 41 页（含原理独有 3 页）、操作版 38 页、参考页 8 页；重写稿的两个目录页不导入（`[[如何订阅claude]]`、`[[如何订阅claude（纯操作版）]]` 指向首页）。第二次运行写入 0 个文件。

### v2 全文比对（#28）

一次性脚本 `scripts/compare-migration.mjs` 比对重写稿 `docs/rewrite/` 和构建产物 `dist/`。脚本不负责构建，先构建再比对：

```bash
npm run build && node scripts/compare-migration.mjs [重写稿目录，默认 docs/rewrite]
```

`dist/` 必须是当前 `src/content/` 构建出来的。改了重写稿之后要先 `node scripts/import-rewrite.mjs` 再重新构建；否则 `src/content/` 还是旧快照，报出来的差异是内容没重跑导入，不是脚本的问题。

- **范围**：`route.yaml` 里的步骤页、选择页、旁支页和参考页，共 49 页；首页（重写稿的目录页）不在比对范围。
- **两种视图**：每页都分别比对**原理视图**（`原理版/<标题>.md` → `dist/<id>/` 里 `data-body="principle"` 的那段）和**操作视图**（`操作版/<标题>.md` → `data-body="operation"` 的那段）。只有一版的页面（原理独有步骤、参考页）只渲染一段不带 `data-body` 的正文，按原理版比。重写稿有这一版、产物里却找不到对应视图的正文时报差异。重写稿里没有操作版时：登记在 `PENDING.operations` 的算待补项（现在没有），其余是原理独有步骤，不算差异；操作版缺失由构建的内容校验把关。
- **命令**：围栏代码块（连同语言标记，去掉 Callout 的 `>` 前缀和公共缩进后逐字比较）；行内代码按渲染出来的正文文字找（表格单元格里的 `` `x` `` 渲染成不带标签的纯文本，产物里没有 `<code>`）。
- **外链**：重写稿正文里的外链（Markdown 链接、裸地址）必须原样出现在该视图的产物里，**地址和链接文字都要对上**，Markdown 链接还要连同前后各 4 个字一起比对（互换地址、改链接文字、把链接挪到别的句子里都会报出来）。围栏代码块和行内代码里的 `https://…` 是命令的一部分，不算外链。产物里的外链必须来自重写稿的链接、登记的双链转换结果，或页面自己生成的（站内导航、参考页的“返回刚才的步骤”）。
- **截图**：重写稿的 `![[文件名|宽度]]` 在该视图的产物里要有同名的图片、宽度一致（重写稿写了宽度才比），且图片文件确实在 `dist/` 里。比的是 `<img>` 的 `alt`：Astro 会把图片转成带哈希的 webp，`src` 不是重写稿里的名字。
- **双链**：重写稿的每条双链都要能解析出来（按标题找页面；带 `#小标题` 的核对锚点存在；`[[04技术/…]]` 查 `blog-links.yaml`；目录页指向首页），产物里的每个站内链接都要能追溯到重写稿的双链或页面生成。
- 都按集合比较：同一条命令、链接或截图在两版重复出现、产物里只剩一处时查不出来，这部分由下面的人工抽查保证。
- **TODO 段落**：每页两种视图合计的 `TODO：` 段数要等于 `PENDING.todos` 的登记（和构建提示“作者待补”的处数一致）；多了、少了或已经补完还登记着，都报差异。
- 退出码沿用旧约定：0 没有差异也没有待补项，1 有未登记的差异，2 只剩登记过的待补项。

**结果（2026-10-16）**：命令差异 **0**、链接差异 **0**、截图差异 **0**，退出码 **2**（只剩登记过的待补项）。比对范围：重写稿原理版 50 个文件、操作版 39 个文件；49 个页面 × 两种视图。登记的待补项：操作版缺失 0 页；作者待补的 TODO 段落 10 页（两种视图合计：`plan1-buy-isp` 4 处，`leak-protection`、`plan1-make-node`、`plan1-panel`、`iphone-proxy`、`iphone-app-store-austria`、`google-appeal`、`android-subscribe` 各 2 处，`ip-tests/decodo`、`ip-tests/qsu-residential` 各 1 处），和构建提示一致。本次比对里实际发生的转换 143 处（站内链接 139、博客外链 3、首页 1），逐条会在运行时打印。

> 审查修正（2026-10-16）：第一版脚本在产物里找不到视图正文时直接跳过，原理独有步骤和参考页（只有一段不带 `data-body` 的正文）共 12 页实际没有比对；`PENDING.operations` 误登记了 9 页“操作版缺失”（重写稿里都有操作版），TODO 按单视图计数、补完的登记查不出来，所以当时退出码是 0。修正后这 12 页也参与比对，新增两条登记过的转换：没写语言的代码块渲染成 `plaintext`；链接上下文里的其他 Markdown 链接按显示的文字取。

## 迁移规则

后续迁移任务都沿用这些规则。规则有变化时先改这里。

1. **只拆分和排版**：命令、链接、优惠码、商家一字不改。需要改动原文字句的地方（例如指向原文旧章节的说法），在对应小节的“改动”一栏逐条写明，交作者确认，确认后标上日期。
2. **正文和原理块**：正文用纯操作版的文字。原理版独有的内容放进 `> [!why] 标题`，原位放在它解释的操作后面（[ADR-0003](adr/0003-principle-content-as-why-callouts.md)）。
3. **原理块标题去掉“为什么：”前缀**：原文写作 `>[!note] 为什么：要先装 Git`，迁移后写成 `> [!why] 要先装 Git`。操作视图的提示行会自己加上“为什么：”（design §4.3），保留前缀会显示成“为什么：为什么：……”。（作者 2026-10-14 选定。）
4. **其他 Callout**：两版都有的 `[!caution]`、`[!note]` 保持原类型。只允许小写的 `why`、`note`、`caution`，不能写成可折叠形式（架构 §3 M1）。`>[!x]` 统一写成 `> [!x]`。
5. **嵌入图片**：去掉 `09附件/` 前缀，只写文件名，例如 `![[文件名.jpg|262]]`。截图复制到 `src/assets/screenshots/`，入库前逐张核对打码（不能露出服务器 IP、节点链接、面板账号）。
6. **双链**：
   - 指向原文章内部小节的双链，改成指向对应步骤或常见问题，例如 `[[step-id]]`、`[[faq/<id>|文字]]`。
   - 指向博客其他文章的双链，改成普通外链。地址规则是 `https://finderlzy.github.io/Writing/<一级目录英文名>/<slug>/#<锚点>`（`04技术` 对应 `tech`，slug 取该文章 frontmatter 的 `slug`）。每条都打开线上页面，核对页面和锚点确实存在。
7. **原文章专有的说明不迁**：原文用来说明“原理版 / 纯操作版两篇文章”或“配套视频只录了哪几节”的句子，在引导站里没有对应的东西，不迁移，在对应小节里写明。
8. **标题下的分隔线**：原文 `## 标题` 下的 `---` 是博客排版，不迁移。
