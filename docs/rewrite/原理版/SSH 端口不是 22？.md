# SSH 端口不是 22？

有的商家后台，除了服务器 IP、用户名、密码，还多写了一个**端口**，是一串四五位的数字。比如我买的 [[实测：丽萨住宅服务器|丽萨住宅服务器]]，后台的“端口”一栏就不是 22。这时候照着正文输 `ssh root@你的服务器IP`，连 `password:` 都不出来，屏幕上提示的是 `ssh: connect to host 你的服务器IP port 22: Connection refused`。

为什么呢？一台服务器上同时跑着好几个程序，SSH 是一个，以后装的节点又是一个。请求送到服务器之后，服务器要知道该交给哪个程序，靠的就是**端口**。你可以把 IP 理解成一栋楼的地址，端口就是楼里的门牌号。SSH 默认住在 22 号，所以 `ssh root@你的服务器IP` 不写端口，敲的就是 22 号的门。

有的商家给 SSH 开的门不是 22 号，而是后台写的那个号码。去敲 22 号，那里根本没有人，自然就连不上。所以只要在命令里告诉 SSH 去敲哪个门：

```bash
ssh -p 你的端口 root@你的服务器IP
```

`你的端口` 换成后台“端口”一栏的数字，`你的服务器IP` 换成真实 IP。`-p` 是小写的，和端口之间有一个空格。后面就和正文一样了：问 `Are you sure...` 时输入 `yes`，出现 `password:` 时输入 root 密码，开头变成 `root@...:~#` 就连上了。

连上以后，运行脚本、导入节点都照正文做。要改的只有连服务器的这一行命令。

还是连不上的话，按 [[SSH 提示 Permission denied？]] 里的第 3 步，直接从商家后台进服务器。
