# 重写稿原样导入，双链按中文标题解析

- 状态：accepted（2026-10-15）

重写稿（`docs/rewrite/`）是 v2.0 唯一的素材来源，作者以后还会改，由作者决定何时重新迁入（需求 FR-01、Q-08）。重写稿里的双链写的是 Obsidian 的文件名，也就是中文标题（`[[选择方案]]`、`[[常见问题#分流规则具体怎么写？]]`），正文末尾有手写的上一步/下一步，TODO 写成普通段落。我们不在迁移时改写正文，而是用脚本把正文原样复制进 `src/content/principle|operation|reference/`，站内页面的英文标识只写在文件名和 `route.yaml` 里；Markdown 插件按标题解析双链、去掉手写页脚、把 `TODO：` 段落转成“作者待补”提示。重新迁入就是重跑导入脚本，再看 git diff。

## Considered Options

- **迁移时把双链改写成英文标识（1.0.0 的做法）**：每次重新迁入都要再手改几百处链接，容易漏改、改错，也让 AC-13 的比对多一层换算。
- **让内容集合直接读 `docs/rewrite/`**：文件名是中文，页面元数据（可跳过、视频、选项块）没地方放；重写稿还在变，站点需要一个“已迁入”的快照（FR-01 要求迁入后单独维护）。

## Consequences

- 全站标题不能重复，两版同名页的标题必须相同，构建时校验；页面改标题等于改链接目标，要和重写稿一起改。
- 页面元数据只能写在原理版文件的 frontmatter 里，导入脚本保留 frontmatter、只替换正文。
- 新增页面要先手建原理版文件和 `route.yaml` 的位置，再跑脚本；脚本只报告，不自动建页、不改路线图。
- 指向博客其他文章的双链（`[[04技术/…]]`）通过 `blog-links.yaml` 映射到外链。
