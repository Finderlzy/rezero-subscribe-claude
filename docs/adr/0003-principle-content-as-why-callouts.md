# 原理内容以 `[!why]` 块内嵌在步骤文件里，视图切换只控制显示

- 状态：superseded（2026-10-15）：v2.0 起原理视图整页换成原理版正文，原理块不再使用，见[需求 §0、FR-30](../requirements.md)。替代方案见 [ADR-0004](0004-whole-page-view-switch.md)

原理版和纯操作版的章节一一对应。原理版多出来的内容基本都是“为什么”说明框，另外还有少量补充句。我们不为两种视图各写一份文件，而是每个步骤一个文件：正文用纯操作版的写法，原理版独有的内容放进 Obsidian Callout `> [!why] 标题`，原位放在它解释的操作后面。原理视图在原位展开这些块，操作视图把它们收起来，只留一行提示。这样既满足 FR-30（原理视图 = 操作内容 + 原理内容），又能在 Obsidian 里直接预览，也能保持作者原来的写作习惯。

## Considered Options

- **每个步骤两个文件（operation.md + principle.md）**：原理和操作的位置对应关系会丢失，两份文件也容易改得不同步。
- **在 frontmatter 里放原理字段**：长段 Markdown 写在 YAML 里很难维护。

## Consequences

- 内容迁移时，原理版独有的补充句也要放进 `[!why]` 块。例如第二章“不管用规则还是全局……”这句，迁移后会从正文挪进原理块，但文字原样保留。
- 两种视图都要显示的提示框继续用 `[!note]`、`[!caution]`，不要写成 `[!why]`。
