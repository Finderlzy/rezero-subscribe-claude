# URL 规则：扁平的英文步骤标识，所属分支由路线图确定

- 状态：accepted（2026-10-13）

已经发布的步骤 URL 不能再改（需求三级边界 Always），改 URL 规则属于 Ask first。所以 URL 规则在首期就定下来：步骤页是 `/<step-id>/`，选择页是 `/choose/<fork-id>/`，常见问题是 `/faq/<faq-id>/`，完成页是 `/done/`。`step-id` 是英文 kebab-case，也是步骤文件的文件名。每个步骤在 `route.yaml` 里只属于一个位置（普通项，或某个分叉点的一个 `branch` 段里的一个或几个选项），所以只看 URL 就能知道它属于哪个分叉点的哪几个选项（S5）。

## Considered Options

- **中文路径**：分享出去时会被编码成很长的 `%E5…`，在聊天软件里不好看，也容易被截断。
- **把章节和选项写进路径**，例如 `/1/plan-3/import-node/`：调整章节归属或选项名时 URL 会跟着变，违反“URL 稳定”。
- **查询参数表示路线**，例如 `?plan=3`：静态托管无法按参数生成不同的页面，分享链接也容易丢掉参数。

## Consequences

- 步骤改名时只改 `title`，不改文件名。确实要换标识时，要先征得作者同意，并保留旧 URL 的跳转页。
- 保留字（v2.0 起为 `faq`、`ip-tests`、`404`、`_astro`）不能用作页面标识，由构建校验保证。
