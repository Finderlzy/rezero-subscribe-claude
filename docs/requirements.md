## 1. 目标与范围

**目的**：把重写稿做成一个独立的引导站。读者每页读一章，用页脚的上一步/下一步推进，照着走就能完成从准备住宅 IP 到订阅 claude 的全过程；需要弄懂原理时直接读同一页里的说明。

**网站名称** [要求]：「Re:从零开始订阅 claude」，取自番剧《Re:从零开始的异世界生活》，同时表示教程从零开始讲。英文副标题「Re:Zero − Starting Life with Claude」。项目仓库名 `rezero-subscribe-claude`。

**目标用户**：作者博客的读者，会用代理但不熟悉这套流程。读者会同时用手机和电脑，通常一边看一边在另一台设备上操作。

**成功标准**：
- 读者选好自己的方案和手机后，一路点“下一步”走完，不需要看别的文章。[要求]
- 需要原理时，同一页里“风控在看什么”“原理：为什么要两层”等小节能直接读到。[要求]
- 重写稿 11 个文件各有自己的页面，路线的分叉和汇合与新稿的章节一致。[要求]
- 页面上没有“默认”标记和任何阅读记录。[要求]
- 站点有自己的 logo，前端视觉按新的设计重做。[要求]

**首期范围（v2.0）**：
- 重写稿的全部页面迁入：两版的同名页合成一个步骤，原理独有步骤、旁支页、参考页按 §5 处理。
- 按 §5 重建路线图和全部 URL。
- 原理/操作两种视图整页切换。
- 去掉默认路线和阅读记录相关的界面和逻辑。
- 新的视觉设计（设计令牌、页面结构）和 logo（含 favicon）。

**非目标**：
- 账号、登录、评论、留言、统计埋点。
- 和博客原文章或重写稿自动同步；重写稿改动后，由作者决定何时迁入。[选定]
- 多语言。
- 旧 URL 的跳转页：站点还没部署过（delivery.md），不存在需要保留的已发布 URL。[选定]
- 由 Agent 撰写重写稿以外的新内容。重写稿里的 TODO 原样保留，按 FR-21 呈现。
- 确定部署位置和域名（Q-01）。

**优先级**：P0 是新路线图 + 新 URL + 整页视图切换 + 去掉默认和记录；P1 是新视觉设计和 logo；P2 是步骤视频。

**v3 范围与优先级（v0.8、v0.9）**：P0 是文档站风格的顶栏、正文栏、侧边栏（FR-72、FR-16）、按作者改完的重写稿合并页面和旧网址跳转（FR-05、FR-25），以及不倒退（AC-31）；P1 是首页（FR-18）和站内搜索（FR-24）。v3 的非目标：作者重写稿以外的路线、URL 和内容改动；全文搜索；顶栏加参考页入口；换框架。（“不固定顶栏”这条已于 2026-10-25 由作者改掉，见 §0.1。）

**v3.1 范围与优先级（v0.13）**：P0 是 M7 更新日志（FR-80–FR-86：条目、分类、排序、置顶和构建校验），P1 是两处入口（FR-87 首页最近 5 条、FR-88 侧边栏底部）。非目标：加第四个以外的分类、从 git 或重写稿自动生成条目、给被改动的页面加“本页有更新”提示（2026-10-23 明确不做）、RSS 或订阅、按标签过滤、分页。

## 3. 三级边界

**Always**
- 每个步骤、选择页、参考页都有稳定的英文标识和独立 URL；v2.0 发布以后，URL 不随内容调整而改变。
- 构建时校验所有链接和路线，失败就阻止构建（FR-61）。
- 推广链接旁保留“是否亲自用过”的说明；前言、免责声明保留成本和风险提示。
- 手机和电脑两种宽度下都能完整阅读和操作。
- 页面不依赖国内无法访问的第三方资源才能显示，例如字体 CDN 或统计脚本。
- **更新条目**写错（类型不认识、缺字段、日期格式不对或写未来日期、超长）时构建失败并指出第几条，和 FR-61 同一口径（v0.13）。

**Ask first**
- 新增、删除或合并分叉点；把某一页移进或移出上一步/下一步序列。
- v2.0 发布后改变步骤标识或 URL 规则。（v3 合并页面造成的标识变化已由作者 2026-10-21 批准，按 FR-25 跳转；合并清单以外的改动仍要先问。）
- 引入需要后端或数据库的能力。
- 改写重写稿的技术操作（命令、脚本版本、商家、优惠码）。迁移时只做拆分和排版，不改实质内容。
- 引入重型前端框架、UI 框架或付费服务。
- 换掉 Astro 或引入现成的文档主题（v3 只学参考站的外观，作者 2026-10-21 选定不换框架）。

## 4. 用户场景与流程

**S1 照做的新读者**：打开首页 → 看到 logo、站名和五章简介 → 点“从第 00 章开始” → 前言 → 整体思路与方案选型 → 在正文末尾选方案二 → 方案二 → 客户端配置与环境验证：电脑端 → 在正文末尾选 iPhone → iOS 准备 → iOS 订阅 → 日常维护 → 后记与致谢 → 回到首页。

**S2 想弄懂原理的读者**：直接读页面里的“风控在看什么”“原理：为什么要两层”“为什么用 Tun 模式”等小节；v3 没有单独的视图切换。

**S3 换方案的读者**：在方案一的页面上，从侧边栏点“换到方案二 →”进入方案二；或在目录里改选，之后的“上一步/下一步”按新路线计算。

**S4 收到答疑链接**：作者把 `/client-desktop/#改时区` 这类链接发给读者。读者在新浏览器打开，直接落到这一页的小节；因为还没选过方案，“上一步”按默认的方案二计算。

**S5 被封号**：在日常维护页读“账号受限之后 → Google 账号被停用”；内容已并进这一页，旧旁支页的网址会跳到这里。

**S6 卡住查问题**：搜索或侧边栏打开 IP 质量实测参考页，看完点“回到”回日常维护；从步骤带 `?from=` 进来时还有“返回刚才的步骤”。

**S7 打开旧网址**：读者打开收藏的 `/plan1-buy-server/` 或 `/register-gmail/`，跳到 `plan1` 的对应小节，或按本机手机选择跳到 iOS/安卓订阅；没有选过手机时落到 `client-desktop` 的选项卡片。

**异常分支**
- 浏览器禁用本机存储或在无痕模式下：功能照常使用，只是关掉页面后选择不保留。
- 读者打开不存在的 URL：显示“找不到这一页”和目录入口。
- 视频平台打不开：显示平台链接和“打不开可换平台/开代理”的提示，不影响阅读正文。

## 6. 功能需求

### 内容

- **FR-01 内容来源** [要求]：步骤和参考页的内容来自重写稿，迁入后在引导站单独维护。重写稿改动后，由作者决定何时重新迁入。
- **FR-02 页面元数据**：每个步骤至少有：标识、标题、所属章节、正文、分叉点选项（选择页）、步骤视频信息（可为空）。v3 起只有一版正文，没有“操作版/原理版”两种元数据。
- **FR-03 内容完整迁移** [要求]：重写稿每个文件里的每一段、每张截图、每个外链和命令，都要在对应页面里出现；命令、链接、优惠码和商家信息保持原样。
- **FR-05 合并页** [要求，v0.9；2026-10-22 作者直接交来合并稿]：重写稿里几个文件合成一个文件后，站点里它们就是一个页面。
  - **由作者合并**：作者已在 `docs/v3-rewrite/` 里按章合并好，站点只按“一页 = 一个文件”导入；Agent 不再执行机械合并，也不改正文。
  - **路线**：合并页在路线图里占一个步骤，所属的分叉点选项、汇合点不变；原页面标题变成合并页的 h2/h3。
  - **可跳过的小节**：被并进合并页的可跳过步骤（如“打开面板”“购买未完成”）不再有跳过按钮，能不能跳过由正文写明。
  - **校验**：FR-61 照旧适用；指向合并页小节的双链和旧网址的跳转目标都必须存在，否则构建失败。
- **FR-25 旧网址跳转** [选定，v0.9；V11 全量]：被合并掉的每个旧标识（如 `/plan1-make-node/`）仍然生成一个页面，打开后立即跳到合并页里对应小节（如 `/plan1/#ssh-连接服务器`）；手机相关的旧页按本机保存的手机选项分流（没选过、读不到或没有 JS 时落到 `client-desktop#下一步`，即选项卡片）；旧 `/faq/<id>/` 跳到对应 h3，`/faq/` 跳到日常维护。没有 JS 时显示一行“这一页已经并入《…》”和链接。旧标识写进跳转表，不能再分给新页面；跳转页不进目录、搜索和 sitemap。旧标识的本机选择（只属于一个选项的页面按选项记住，FR-17）在跳转后照常生效。
- **FR-04 写法转换**：重写稿的 Markdown 和 Obsidian 写法（相对链接、`|宽度` 嵌入、表格、代码块）正确呈现。站内相对链接改成站内链接；指向博客其他文章的链接按 Q-11 处理。页脚的“上一步/下一步”由路线图生成，正文末尾手写的页脚不显示。

### 页面与导航

- **FR-10 一页一步**：沿用。页面顶部显示章节名和本章进度，页脚显示“上一步”和“下一步”（写出目标页的标题；v3 起是文字链接，见 FR-72）。进度按读者当前路线计数（只有一版正文）；某个分叉点未选、无法确定总数时，只显示章节名。
- **FR-11 上一步/下一步** [要求]：按读者当前路线计算。后记是路线的最后一页，它的“下一步”是“回到首页”（v3 不再有附录）。
- **FR-12 分叉点选择页** [要求]：分叉点的选择就在正文页末尾（`overview`、`client-desktop`），不是单独一页；选项卡片由页面 frontmatter 的 `options` 生成。每个选项是一块可点击区域，**不写“默认”字样**；路线图写了 default 的分叉点（`overview` 的方案二），该选项标题后标“推荐”，本机没选时按已选的样子高亮它（不标“当前选择”）[要求，2026-10-20]。选择后进入该选项的第一个步骤，并记住选择。已经选过时，标出“当前选择”。选择页的“下一步”：已选时进入所选选项的第一步；未选时不显示“下一步”。
- **FR-13 汇合与未选** [要求]：分支最后一步的“下一步”指向下一章的第一页；它的“上一步”指向所选分支的最后一步。节点方案默认方案二（v0.6）：没选时按方案二计算，`overview` 的“下一步”是“方案二：配置住宅 IP 服务器”，`client-desktop` 的“上一步”也是它；默认不写入本机选择，选择页不标“已选”。手机系统没有默认：未选时，`maintenance` 的“上一步”指向 `client-desktop`；手机分支的“下一步”指向 `client-desktop`。
- **FR-14 改变路线**：沿用。读者可以随时在目录或选择页改选，之后的导航按新路线计算。
- **FR-15 可跳过步骤**：v3 的新稿里没有可跳过的整页步骤（“打开面板”“购买未完成”等都是正文小节），页面上不再出现“跳过”按钮。
- **FR-16 目录**：首页和任意页面都能看到目录：宽度 ≥720px 时，步骤页、选择页和参考页左侧常驻目录侧边栏（独立滚动），以下是从顶栏“目录”打开的抽屉（v0.8，原为 ≥1100px）。v3 起 [选定]：只展开当前页所在的章，其他章只显示章名，点章名展开或收起（折叠只影响显示，不写入本机选择）；当前页下面列出正文里的 h2，点击跳到对应位置；没有 h2 的页面不列。目录按章列出全部步骤；分叉点同时列出全部选项，选中的（或当前页所在的）选项展开、其余收起，点选项名只开合；当前步骤高亮。**章名和步骤都不写数字**（没有“第 n 章”）。目录里**没有**已读标记和“清除进度”。参考页列在“日常维护”章末尾，不再固定挂在最后一章。
- **FR-17 独立 URL**：每个步骤、选择页、参考页、首页都有独立且稳定的 URL，可以直接打开、刷新、分享。只属于一个分支的步骤，打开时按它所属的选项计算导航，并记住这个选项。

- **FR-81 四个分类和默认分类** [选定，作者 2026-10-23]：页面顶部一排分类：「全部」「公告」「内容」「站点」，**进来默认选中「全部」**。选区不写进 URL、不写本机，刷新或再进来都是「全部」；分类不是四个独立页面。
- **FR-82 没有 JS 时的分类** [选定]：没有 JS 时四个分类的条目**都**渲染在页面上（顺序：全部、公告、内容、站点），能完整读到；有 JS 时只显示选中的那个分类。旧版浏览器或不支持脚本时退化为“全部展开”，和站里其他页面“没有 JS 也能完整读”的口径一致。
- **FR-83 更新条目** [要求]：一条**更新条目**有四个必填字段：**发布日期**（`YYYY-MM-DD`，原样显示）、**更新类型**（`notice` / `content` / `site`，即公告 / 内容 / 站点）、**标题**（一句话，≤40 个字符）和**内容**（≤200 个字符）；另有可选的 `page`：被改动的页面标识，写了就渲染成指向该页的文字链接（文字取该页标题）。页面不存在时构建失败。条目里不放多段正文、图片和代码块。
- **FR-84 排序和置顶** [选定]：同一分类里按发布日期倒序；同一天的条目保持 `update-log.yaml` 里的书写顺序（建议新的写最上面，构建不强制）。**公告**可以标 `pinned: true`：标了的在「全部」和「公告」里排在所有条目前面（仍按日期倒序），「内容」「站点」里不生效。只有公告能置顶，别的类型写了 `pinned` 构建失败。
- **FR-85 条目数据的位置** [要求]：唯一来源是 `src/content/update-log.yaml`，由作者维护（字段、类型和样例写在该文件的注释里），**不从 git 提交、代码改动或重写稿自动生成**；它不是**正文**，不受 ADR-0005 的“原样导入”约束，也不进 Obsidian 重写稿目录。新增条目只改这一个文件。
- **FR-86 内容校验** [要求]：缺字段、更新类型拼错、日期格式不对、日期晚于构建当天、标题或内容超长、`pinned` 用在非公告上、`page` 指向不存在的页面、文件不是合法 YAML，都让构建失败并指出第几条（从 1 数）。某个分类没有条目时，分类照样显示，点进去写“这一类还没有更新”。
- **FR-87 首页的最近 5 条** [要求]：首页五章简介下面、页脚上面加一节“最近更新”：取「全部」排序最前的 5 条（含置顶），**和五章简介一样横着排**（桌面 5 列一行、平板 3 列、手机一列），每列内部竖着排发布日期、更新类型和标题，标题整条是链接（有 `page` 时链到那一页，否则链到 `/update-log/`）；这一节标题旁有“查看全部 →”指向 `/update-log/`。**首屏和五章简介块不动**，不加提示条；排版沿用首页现有风格，不新造卡片（作者 2026-10-25 改成横排）。
- **FR-88 侧边栏底部的入口** [要求]：每个有目录的页面（步骤页、参考页、更新日志页）在 ≥720px 的侧边栏底部和 <720px 的抽屉底部都有一条常驻的“更新日志”入口，**固定在底部、不跟着目录滚走**，链接到 `/update-log/`；在更新日志页自己上，这一项是当前态（和侧边栏当前页一样的主色竖线）。首页没有侧边栏，入口靠 FR-87 的“查看全部”。
